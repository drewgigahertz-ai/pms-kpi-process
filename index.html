Prototype for the dev team

PMS KPI Process

Managers build forms and schedule them as tasks. Employees submit. The schedule sets the deadline. The head pivots each form into a table or chart. Each submission records its timestamp and timeliness, and completeness is measured against the required number of reports. Data stays in this browser.

Build the form

Every question becomes a column in Responses and a field you can pivot on. Deadlines, assignees and reviewers are set in Schedule Set Up, outside the form.

Schedule Set Up

Set the deadline for submissions: when it ends, who must submit, who reviews, and which forms they fill in.

People list ()

Assignees and reviewers are picked from this list. In the real system it comes from the employee directory.

Accuracy Set Up

Pick which existing forms are rated for accuracy, who is rated (Ratee), on which KPI, and who rates them (Rater). The rater is separate from Reviewer 1.

Workflow

  1. Ratee submits the form in Collect, as usual.
  2. Rater gets it in their To rate list in Collect.
  3. Rater scores accuracy from 0 to 100% and can add a comment.
  4. Accuracy % appears in Responses and as a value in the pivot.

Fill and submit

This is what respondents see: the tasks assigned to them, each with its deadline and forms. Each submission is saved as one row.

For developers: the data at each step

The app keeps three objects. The form schema defines questions. Each response stores answers keyed by question id. The pivot config plus chart type is all the visualization needs, so it can be saved as a "view" alongside the form.
